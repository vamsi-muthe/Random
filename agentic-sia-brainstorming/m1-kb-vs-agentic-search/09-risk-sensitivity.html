9. Risk Assessment & Sensitivity Analysis

What could make this decision wrong? What variables swing the outcome? How robust is the recommendation?

Why this matters: A cost analysis is only useful if you know which assumptions can break it. This section stress-tests the recommendation: what if token prices rise? What if we need real-time latency? What if volumes explode? The answer: the decision is robust across all realistic scenarios.

9.3 What-If Scenarios

Verdict: Even with 2x price increase, agentic remains 10x+ cheaper. The recommendation is stable.

What if we need <5s retrieval latency?

This is the ONE scenario where KB wins. If a hard SLA of <5s per retrieval is imposed, agentic's 2-3s per tool call x 7 calls = 14-21s per entity is too slow. Mitigations: pre-warm common patterns, aggressive result caching, or hybrid (KB for first pass, agentic for cross-file resolution). This SLA is not projected for an async review pipeline.

9.4 Decision Robustness

This decision is robust. Across all realistic stress tests:
  • 2x token price increase: Agentic still wins (10x+ cheaper)
  • 5x volume increase: Agentic still wins (3-10x cheaper)
  • Zero maintenance for KB: Agentic still wins (infra alone is 5x more expensive)
  • Only scenario where KB wins: hard <5s latency SLA (not applicable)

The recommendation would only reverse at >1,200 SIAs/month WITH a <5s latency requirement WITH prompt caching disabled. None of these conditions are projected.
